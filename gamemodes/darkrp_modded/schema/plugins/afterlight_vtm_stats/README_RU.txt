AFTERLIGHT VTM CHARACTER SHEET v1.8
Единый категоризированный чарлист VTM и дисциплин для Helix

ИЗМЕНЕНИЯ v1.8 — ЕДИНЫЙ МАКСИМУМ ПЯТЬ
=======================================
- Максимальный уровень каждой дисциплины изменён с 8 на 5.
- Дисциплины теперь используют такую же пяти-точечную шкалу, как Характеристики, Способности и Добродетели.
- Серверная нормализация, административные команды, свободная вместимость и подтверждение автоматически ограничены значением 5.
- Сохранённые уровни 6–8 безопасно нормализуются до 5 при чтении и будут записаны в новом диапазоне при следующем изменении данных дисциплин.

ИЗМЕНЕНИЯ v1.7 — ВЫДАЧА ДИСЦИПЛИН И РАСПРЕДЕЛЕНИЕ ОЧКОВ
========================================================
- Категория `ДИСЦИПЛИНЫ` возвращена к общей красно-чёрной палитре чарлиста; отдельный фиолетовый цвет удалён.
- Выдача дисциплины и повышение уровня теперь строго разделены.
- `Добавить (0)` регистрирует выбранную дисциплину в чарлисте с уровнем 0 и без бесплатного повышения.
- Явно выданная нулевая дисциплина уже отображается владельцу. Отсутствующая дисциплина не отображается вообще.
- В общий административный ряд выдачи очков добавлена четвёртая категория `Дисциплины`.
- Свободные дисциплинарные очки показываются в заголовке категории и распределяются игроком теми же обратимыми точками.
- Подтверждение сохраняет обычные статы и дисциплины одной серверно проверяемой операцией и требует распределить все четыре резерва.
- Добавлены отдельные административные действия `Удалить выбранную` и `Очистить дисциплины`, оба удаляют строки из чарлиста; удаление выбранной дисциплины требует подтверждения.
- При удалении последней дисциплины или полной очистке скрытый дисциплинарный резерв обнуляется. При удалении одной из нескольких дисциплин резерв ограничивается вместимостью оставшихся строк.
- Обычная очистка чарлиста по-прежнему сохраняет выданные дисциплины, уровни и свободный дисциплинарный резерв.
- Старые положительные уровни автоматически считаются выданными. Старые нулевые placeholder-записи не возвращаются: новая нулевая строка хранится только с явным маркером `unlocked = true`.

======================================
- Функциональность Afterlight Disciplines Core v1.1 перенесена в VTM Stats: реестр, нормализация, серверные API, команды и журналирование теперь поставляются одним плагином.

- В административном листе добавлены выбор дисциплины и установка точного уровня 0–5. Ноль удаляет выбранную дисциплину.

- Сохранены публичные API и пространство имён `ix.disciplines`, поэтому будущие клановые выдачи и плагины активных сил смогут подключаться без миграции данных.
- Хранилище остаётся существующим сервер-авторитетным character var `vampireDisciplines` из Vampire Foundation. Данные игроков не переносятся и не теряются.

ВАЖНО: отдельный `afterlight_disciplines_core` после установки v1.8 необходимо удалить из schema/plugins. Его одновременная установка создаёт дублирующую старую UI-обвязку и повторную регистрацию команд. Vampire Foundation v1.10 по-прежнему необходим.

БЮДЖЕТЫ И ПРЕДЕЛЫ
=================
Все показатели имеют максимум 5.

Человек при создании получает:
- 12 распределяемых очков Характеристик;
- 17 распределяемых очков Способностей;
- 7 распределяемых очков Добродетелей.

Каждая Характеристика и Добродетель имеет базовую точку 1. Способности начинаются с 0. Эти базовые точки не вычитаются из распределяемого резерва.

При первом обращении в вампира добавляется:
- +3 свободных очка Характеристик (итоговый бюджет 15);
- +8 свободных очков Способностей (итоговый бюджет 25);
- Добродетели не изменяются и сохраняют бюджет 7.

`vampireBonusGranted` блокирует повторное получение бонуса через `/VampireRemove` и повторное обращение.

ДИСЦИПЛИНЫ
===========
Встроенный реестр содержит 21 дисциплину из Disciplines Core v1.1: animalism, celerity, vicissitude, potence, dominate, presence, auspex, dementation, fortitude, protean, thanatosis, obfuscate, obtenebration, chimerstry, valeren, necromancy, serpentis и четыре пути thaumaturgy.

Уровни находятся в диапазоне 0–5. Отсутствие записи означает, что дисциплина не выдана и не видна. Явно выданная запись с `unlocked = true` и уровнем 0 уже создаёт строку, но не даёт механического уровня. Людям выдача и очки дисциплин запрещены сервером.

Администратор сначала добавляет дисциплину на нуле, затем отдельно выдаёт свободные очки категории `disciplines`. Игрок распределяет их в TAB и подтверждает вместе с остальными резервами. Родной клановый набор пока не выдаётся автоматически; его последующая реализация должна сначала вызывать `ix.disciplines.Grant`, а стартовые/свободные очки — `ix.vtm.stats.AddPoints(character, "disciplines", amount, source)`. Прямой `SetLevel` работает только для уже добавленной дисциплины.

ИНТЕРФЕЙС
=========
Один `AfterlightVTMStatSheet` используется и в создании персонажа, и в TAB → Персонаж. Характеристики и Способности разделены на три колонки, Добродетели показаны отдельным центральным блоком. У вампира с хотя бы одной явно выданной дисциплиной ниже появляется динамический блок `ДИСЦИПЛИНЫ`, включая строки уровня 0; при пустом списке блок полностью отсутствует.

При создании клик по точке устанавливает значение; клик по последней заполненной точке уменьшает его. После распределения всех трёх резервов нужно нажать `ПОДТВЕРДИТЬ`; с остатком очков или без подтверждения сервер не создаст персонажа.

В TAB новые изменения сначала существуют как черновик. До подтверждения их можно уменьшать до последнего серверно сохранённого значения. Кнопка `ПОДТВЕРДИТЬ` отправляет весь прирост одной транзакцией. После успешного подтверждения эти точки становятся постоянными и бесплатный возврат запрещается. Сервер самостоятельно проверяет ID, резерв, vampire-only ограничения и максимум.

Старый визуальный блок Helix `Атрибуты` скрывается, но его данные не удаляются. Будущие оружие, навыки и проверки должны использовать `ix.vtm.stats`.

МИГРАЦИЯ С v1.0
================
Миграция выполняется один раз по `version = 2`:
- старые Bloodlines ID `dodge`, `security`, `scholarship` переводятся в `athletics`, `larceny`, `academics`;
- остальные совпадающие вложения сохраняются;
- человеку добавляется разница бюджетов +5 Характеристик и +7 Способностей;
- уже обращённому вампиру добавляется разница до новых итогов: +3 Характеристики и +9 Способностей;
- всем добавляется новый резерв 7 Добродетелей.

Для старого вампира +9 Способностей является корректной миграцией: в v1.0 он имел 10+6=16, а теперь должен иметь 17+8=25. Новое обращение человека выдаёт ровно +8.

API
===
`ix.vtm.stats.GetDefinition(id)`
`ix.vtm.stats.GetCategory(id)`
`ix.vtm.stats.GetData(character)`
`ix.vtm.stats.Get(character, id)`
`ix.vtm.stats.GetUnspent(character, category)`
`ix.vtm.stats.GetPool(character, ...)`

Сервер:
`ix.vtm.stats.SetData(character, data, saveNow)`
`ix.vtm.stats.Migrate(character)`
`ix.vtm.stats.AddPoints(character, category, amount, source)`
`ix.vtm.stats.Reset(character, actor)`
`ix.vtm.stats.SpendPoint(character, id, source)`
`ix.vtm.stats.Commit(character, proposedValues, source)`
`ix.vtm.stats.Set(character, id, value, actor)`

Встроенный API дисциплин:
`ix.disciplines.ResolveID(id)`
`ix.disciplines.Get(id)`
`ix.disciplines.GetNativeDisciplines(character)`
`ix.disciplines.IsNative(character, disciplineID)`
`ix.disciplines.Normalize(data)`
`ix.disciplines.GetCharacterData(character)`
`ix.disciplines.GetLevel(character, disciplineID)`
`ix.disciplines.IsGranted(character, disciplineID)`
`ix.disciplines.Has(character, disciplineID, minimumLevel)`

Только сервер:
`ix.disciplines.Grant(character, disciplineID, actor, context)` — добавить видимую дисциплину уровня 0.
`ix.disciplines.Remove(character, disciplineID, actor, context)` — полностью удалить выбранную дисциплину.
`ix.disciplines.SetLevel(character, disciplineID, level, actor, context)` — точная административная установка уже выданной дисциплины.
`ix.disciplines.AddLevel(character, disciplineID, amount, actor, context)`
`ix.disciplines.Clear(character, actor, context)`

Примеры будущих пулов:
```lua
local ranged = ix.vtm.stats.GetPool(character, "perception", "firearms")
local melee = ix.vtm.stats.GetPool(character, "strength", "melee")
local hacking = ix.vtm.stats.GetPool(character, "wits", "computer")
local stealth = ix.vtm.stats.GetPool(character, "dexterity", "stealth")
local courage = ix.vtm.stats.Get(character, "courage")
```

КОМАНДЫ
=======
`/VTMCharacterSheet <игрок>` — открыть полный лист в административном окне. В нём можно выдать свободные очки каждой категории или полностью очистить лист.
`/VTMStats <игрок>` — остатки трёх резервов.
`/VTMStatSet <игрок> <stat_id> <значение>` — административная установка base–5.
`/VTMPointsAdd <игрок> <attributes|abilities|virtues|disciplines> <число>` — изменение свободного резерва.
`/DisciplineCatalog` — каталог стабильных ID дисциплин.
`/DisciplineList <игрок>` — все выданные дисциплины, включая уровень 0.
`/DisciplineGrant <игрок> <id>` — добавить дисциплину с уровнем 0.
`/DisciplineRemove <игрок> <id>` — полностью удалить выбранную дисциплину.
`/DisciplineSet <игрок> <id> <0–5>` — административно установить уровень уже выданной дисциплины; 0 сохраняет её видимой.
`/DisciplineAdd <игрок> <id> <число>` — административно прибавить или снять уровни уже выданной дисциплины.
`/DisciplineClear <игрок>` — удаление всех дисциплин и дисциплинарного резерва.

Все команды изменения и полный чужой чарлист доступны только администрации. Князь, Епископ, Барон и другие лидеры faction не получают эти полномочия.

БЕЗОПАСНОСТЬ
============
Клиентский черновик статов полностью перепроверяется сервером относительно неизменяемой сохранённой базы и резервов. Административные запросы дисциплин повторно проверяют `client:IsAdmin()`, активного персонажа, вид вампира, ID и диапазон уровня. `afterlightVTMStats` и `vampireDisciplines` являются локальными character vars владельца; чужой полный лист выдаётся только сервером авторизованному администратору. Net-запросы ограничены по частоте. `InitPostEntity` ничего не возвращает и не блокирует HP/stamina или `ix.option.Sync`.
